Routing

Requests are matched against your route table in order. The first match wins, so put specific patterns above catch-alls.

Defining routes

Routes live in orbit.toml at the root of your project.

orbit.toml12 lines
[[routes]]
pattern = "/api/*"
service = "api-gateway"
timeout = 30

[[routes]]
pattern = "/*"
service = "edge-router"

Order matters

A catch-all above a specific pattern will shadow it entirely.

01What counts as a build minute?

Wall-clock time from the first build step to the upload finishing, rounded up to the next minute per build. Cached steps that are skipped cost nothing.

Nothing stops. You get an email at 80% and 100%, and overage is billed at the published rate:

  • Bandwidth: $0.15 per GB
  • Build minutes: $0.01 per minute
03Can I bring my own domain?

Yes, on every plan. Point a CNAME at edge.orbit.app; certificates are issued within a minute and renew on their own.

Node 20 and 22, Bun, Deno and any static output. Set it per project in orbit.toml.

Build artefacts live in the region you pick at project creation. Logs are kept for 30 days and never leave that region.

p95 is a lie your dashboard tells you

A single percentile hides the shape of the distribution. Here is what we alert on instead, and the incident that changed our minds.

AEAryan EbrahimpourSep 11, 20268 min read

One Tuesday in July our p95 latency looked perfect: 88ms, flat all afternoon. Meanwhile 4% of checkout requests were timing out. The dashboard was right about p95, but p95 was the wrong thing to be watching.

The shape matters

A percentile is one point on a curve. Two very different services can share a p95:

  • A tight distribution with a clean tail
  • A bimodal one, where a slow path serves a few percent of traffic
  • A healthy body with a cliff at p99.5 that a p95 never sees

We were not measuring the service. We were measuring one number the service happened to produce.

What we alert on instead

We now keep a full histogram per route and alert on the share of requests over budget, which is closer to what a user feels. The query is short:

alert.sqlsql
SELECT route,       count_if(latency_ms > budget_ms) / count(*) AS over_budgetFROM requestsWHERE ts > now() - INTERVAL '5 minutes'GROUP BY routeHAVING over_budget > 0.01;

Budgets are per route

Checkout gets 300ms, image resizing gets 2s. One global budget recreates the p95 problem.

Results

  1. Pages per week fell from 14 to 3
  2. Every remaining page mapped to user-visible impact
  3. Median time to detect dropped from 11 to 2 minutes

Rewrites

A rewrite serves a different path than the one requested, without changing the URL the visitor sees.

Install the SDK if you want to define rewrites in code rather than in orbit.toml:

terminal
npm install @orbit/sdk
terminal
pnpm add @orbit/sdk
terminal
bun add @orbit/sdk

Regex captures

Patterns may use named groups. Each group is available in the destination as :name.

orbit.tomltoml
[[rewrites]]source      = "/blog/(?<slug>[a-z0-9-]+)"destination = "/posts/:slug.html"status      = 200

Parameters

KeyTypeDefaultDescription
sourcestring—Path or regex to match. Required.
destinationstring—Path to serve instead. Required.
statusnumber200Response status to send.

Rewrites run after redirects

A redirect that matches first will win. Check matching order.

Advanced

Rewriting to an external origin

Set destination to a full URL. Orbit proxies the request and streams the response back; caching headers from the origin are respected.

Preserving the query string

Query strings are forwarded by default. Set query = "drop" to strip them.

Limits
  • 1,024 rewrites per project
  • Patterns up to 4 KB
  • No lookbehind in regex
